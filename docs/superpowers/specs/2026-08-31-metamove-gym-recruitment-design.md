# 메타무브짐 PT 트레이너 채용 사이트 설계

## 1. 목적과 범위

메타무브짐의 신입·경력 퍼스널 트레이너 채용을 위한 신규 웹사이트를 설계한다. 현재는 단일 센터를 소개하지만 향후 여러 지점으로 확장할 수 있어야 한다.

사이트는 세 영역으로 분리한다.

1. 공개 채용 사이트: 센터, 지향점, 확장 목표, 복지·혜택, 근무 규정, 입사 후 얻는 것, 대표 2인의 전문성, 채용 포지션을 소개한다.
2. 지원 영역: 자기소개서를 작성하고 이력서를 첨부하는 5단계 지원서를 제공한다.
3. 관리자 영역: 지원자를 검색·검토하고 상태, 평가, 메모를 관리한다.

이번 단계의 산출물은 디자인과 기술 설계 문서다. 화면 구현, DB 생성, 배포, 실제 개인정보 수집은 포함하지 않는다.

## 2. 성공 기준

- 신입과 경력 지원자가 첫 화면에서 성장·보상·확장이라는 핵심 제안을 이해한다.
- 실제 센터와 대표 2인의 전문성이 주장을 증명한다.
- 혜택과 근무 규정이 지원 전에 쉽게 비교된다.
- 모바일에서 지원 CTA가 항상 명확하고 지원서 입력이 잘리지 않는다.
- 지원자는 자기소개서와 이력서를 안전하게 제출하고 접수 완료를 확인한다.
- 관리자는 지원자 검색, 상세 검토, 상태 변경, 평가, 메모를 수행한다.
- 공개 사용자는 제출된 개인정보와 파일을 읽을 수 없다.

## 3. 선택한 디자인 방향

`증거 중심 균형형 에디토리얼 시스템`을 사용한다.

- 흰색과 옅은 회청색을 넓은 정보 표면으로 사용한다.
- 딥 네이비는 제목, 구조선, 신뢰 구간에 사용한다.
- 밝은 블루는 주요 CTA, 현재 단계, 핵심 인덱스에 제한한다.
- 실제 센터·대표 사진과 명확한 텍스트를 우선하고 장식성 이미지는 사용하지 않는다.
- 정보 위계는 여백, 숫자, 정렬로 만들고 동일 크기 카드 반복을 피한다.

세부 토큰과 레퍼런스 매핑은 프로젝트 루트의 `DESIGN_BRIEF.md`를 따른다.

## 4. 정보 구조

### 4.1 공개 사이트

상단 내비게이션은 `메타무브짐 / 성장과 비전 / 대표 소개 / 혜택·규정 / 채용 포지션 / 지원하기`로 구성한다.

홈페이지 섹션 순서는 다음과 같다.

1. Hero: 실제 센터 사진, `좋은 트레이너가 오래 성장하는 시스템.` 헤드라인, 채용 포지션 CTA.
2. ValueIndex: `01 성장 / 02 보상 / 03 확장`의 세 기준.
3. CenterStory: 센터 소개, 운영 철학, 회원에게 제공하는 가치.
4. ExpansionVision: 현재 단일 센터와 향후 다지점 확장 방향. 확정된 사실만 사용한다.
5. FounderPair: 대표 2인의 사진, 경력, 전문 분야, 지원자 성장과의 연결.
6. GrowthTabs: 신입과 경력 지원자가 입사 후 얻는 교육, 고객 경험, 개인 브랜드, 리더십, 지점 확장 참여 가능성.
7. BenefitsAndRules: 복지·제공 혜택을 먼저 강조하고 근무시간, 급여, 휴무, 복장, 고객관리 원칙을 표와 펼침 항목으로 제공.
8. OpenPositions: 신입·경력 포지션, 자격 조건, 우대사항, 채용 절차.
9. FinalCTA: 별도 지원 페이지 이동.

### 4.2 지원 영역

별도 `/apply` 경로에 다음 5단계를 제공한다.

1. 기본 정보: 이름, 연락처, 이메일, 신입·경력 구분, 희망 시작일.
2. 경력·자격: 경력 기간, 근무 이력, 자격증, 전문 분야. 신입·경력 선택에 따라 필드를 조건부 표시한다.
3. 자기소개서: 지원 동기, 트레이너로서의 강점, 메타무브짐에서 이루고 싶은 목표. 문항별 글자 수와 입력 기준을 표시한다.
4. 서류 첨부: 이력서 필수, 추가 포트폴리오 선택. 허용 형식과 파일당 10MB 제한을 명시한다.
5. 검토·제출: 모든 답변, 첨부 파일, 개인정보 동의를 확인하고 섹션별 수정 링크를 제공한다.

제출 성공 후 접수번호와 이후 전형 절차만 표시하며 민감한 답변을 다시 노출하지 않는다.

### 4.3 관리자 영역

별도 `/admin` 경로를 사용한다.

- 요약: 전체, 신규, 검토 중, 면접 예정 인원.
- 목록: 이름, 신입·경력, 경력 요약, 핵심 자격, 지원일, 상태.
- 검색·필터: 이름, 지원 구분, 전문 분야, 지원일, 상태.
- 상세: 기본 정보, 경력, 자격, 자소서, 첨부 파일.
- 평가: 종합 평가, 내부 메모, 상태 변경, 다음 일정.
- 상태: `신규 / 검토 중 / 면접 예정 / 합격 / 불합격`.
- 감사 정보: 변경 관리자와 변경 시각을 상태 이력에 기록.

데스크톱에서는 목록·상세 분할 화면을 사용하고 태블릿 이하에서는 목록에서 상세로 순차 이동한다.

## 5. 컴포넌트 경계

- `PublicShell`: 공개 내비게이션, 푸터, 모바일 고정 지원 CTA.
- `HeroEvidence`: 첫 메시지, 실제 센터 사진, ValueIndex 연결.
- `EvidenceRail`: 성장·보상·확장의 숫자, 주장, 실제 근거, 섹션 링크.
- `FounderPair`: 대표 2인의 상호 보완 전문성을 한 구성으로 표현.
- `GrowthTabs`: 신입·경력별 내용을 전환하며 탭 접근성 규칙을 준수.
- `BenefitsAndRules`: 혜택 강조부와 근무 규정 표·아코디언.
- `PositionSummary`: 모집 조건과 전형 절차.
- `ApplicationStepper`: 현재 단계, 완료 단계, 오류 단계, 임시 입력 상태.
- `ApplicationReview`: 제출 전 요약과 섹션별 수정.
- `ApplicantTable`: 검색, 필터, 정렬, 빈 결과.
- `ApplicantDetail`: 지원 내용과 비공개 첨부 파일 접근.
- `ReviewPanel`: 상태, 평가, 메모, 다음 일정.

각 컴포넌트는 표시 데이터와 이벤트만 입력받고, DB 접근은 데이터 계층과 서버 API에 둔다.

## 6. 기술 구조와 비용

초기 무비용 운영을 위해 다음 구성을 사용한다.

- 프런트엔드: React 기반 정적·클라이언트 화면.
- 호스팅과 서버 API: Cloudflare Pages 및 Pages Functions 무료 범위.
- 데이터베이스, 관리자 인증, 비공개 파일 저장: Supabase Free.
- 도메인: 기존 도메인을 연결하거나 Cloudflare 기본 주소를 사용한다. 신규 맞춤 도메인 구매비는 무료 범위에 포함되지 않는다.

Vercel Hobby는 상업적 사용 제한이 있어 사용하지 않는다. 무료 서비스 한도를 넘거나 안정성·백업·감사 로그 요구가 커지면 유료 전환을 별도 승인받는다.

## 7. 데이터 모델

- `applications`: 접수번호, 지원 구분, 기본 정보, 경력 요약, 전문 분야, 제출 시각, 현재 상태.
- `application_answers`: 지원서 ID, 문항 키, 답변, 표시 순서.
- `application_files`: 지원서 ID, 비공개 저장 경로, 원본 파일명, MIME, 크기, 파일 종류.
- `admin_profiles`: 인증 사용자 ID, 표시 이름, 역할, 활성 여부.
- `application_reviews`: 지원서 ID, 관리자 ID, 종합 평가, 내부 메모, 수정 시각.
- `application_status_history`: 지원서 ID, 이전·새 상태, 관리자 ID, 변경 시각, 내부 사유.

지원자 개인정보와 내부 평가를 분리해 권한 정책과 보관·삭제 작업을 독립적으로 적용한다.

## 8. 데이터 흐름

### 8.1 제출

1. 브라우저가 필수 항목, 글자 수, 파일 확장자·MIME·10MB 제한을 검사한다.
2. Cloudflare 서버 API가 동일한 검사를 반복하고 요청 빈도와 비정상 입력을 제한한다.
3. 서버가 난수 접수번호와 비공개 파일 경로를 만든다.
4. 이력서를 비공개 저장소에 저장하고 지원자·답변·파일 메타데이터를 DB에 기록한다.
5. 전체 성공 시 접수 완료 응답을 반환한다.
6. DB 기록이 실패하면 방금 저장한 파일을 삭제하고 일반화된 오류를 반환한다.

### 8.2 관리자 조회

1. Supabase Auth로 관리자를 인증한다.
2. 서버와 DB 정책이 활성 관리자 역할을 확인한다.
3. 목록에는 검토에 필요한 최소 정보만 반환한다.
4. 상세 요청 시 지원자, 답변, 평가, 상태 이력을 조회한다.
5. 이력서 다운로드 시 짧게 만료되는 임시 접근 주소를 발급한다.
6. 상태·평가·메모 변경 시 관리자 ID와 시각을 기록한다.

## 9. 보안과 개인정보

- 모든 지원자 테이블에 행 단위 접근 정책을 적용한다.
- 공개 익명 역할은 서버 API를 통한 제출 외 읽기·수정·삭제 권한이 없다.
- 스토리지 버킷은 비공개이며 영구 공개 URL을 만들지 않는다.
- 서버 비밀키는 Cloudflare 환경 변수에만 저장하고 브라우저 번들에 포함하지 않는다.
- 관리자 세션 만료와 로그아웃을 제공한다.
- 오류 메시지에 DB 구조, 저장 경로, 사용자 개인정보를 포함하지 않는다.
- 개인정보 동의문에는 수집 항목, 목적, 보관기간, 거부권과 불이익을 포함해야 한다.
- 회사가 승인한 개인정보 동의문과 보관기간이 제공되지 않으면 실제 지원서 제출 기능을 공개하지 않는다.
- 보관기간이 지난 지원서, 답변, 파일, 평가, 상태 이력의 삭제 정책을 동일하게 적용한다.

## 10. 오류와 상태 설계

- 초기 상태: 작성 전에 필요한 정보와 예상 소요를 표시.
- 입력 오류: 상단 오류 요약과 해당 필드 오류를 함께 표시하고 색상만으로 구분하지 않음.
- 파일 오류: 허용 형식, 실제 형식, 크기 제한을 구체적으로 안내.
- 업로드 중: 진행 상태와 중복 제출 방지.
- 네트워크 오류: 입력 내용을 보존하고 재시도 제공.
- 제출 성공: 접수번호와 다음 절차 표시.
- 관리자 빈 상태: 필터 결과 없음과 전체 지원자 없음 구분.
- 접근 거부: 로그인 필요와 권한 부족을 분리하되 내부 권한 구조는 노출하지 않음.

## 11. 접근성과 반응형

- 모든 필드에 지속적으로 보이는 라벨을 둔다.
- 키보드 포커스를 명확히 표시하고 단계 전환 후 제목으로 초점을 이동한다.
- 상태와 오류는 아이콘·텍스트·형태를 함께 사용한다.
- 한국어 본문 줄간격과 줄 길이를 유지하고 과도한 음수 자간을 사용하지 않는다.
- 320, 360, 390, 430px에서 가로 스크롤, 버튼 줄바꿈, 상태표시 잘림을 검사한다.
- 모바일에서 고정 지원 CTA가 입력 필드나 제출 버튼을 가리지 않는다.
- `prefers-reduced-motion`에서는 모든 모션을 즉시 최종 상태로 표시한다.

## 12. 콘텐츠 입력 및 공개 조건

구현 전에 사용자가 다음 실제 자료를 제공한다.

- 공식 로고 원본과 사용 규칙.
- 센터 사진과 사용 권한 확인.
- 대표 2인의 이름, 사진, 경력, 전문 분야와 공개 승인.
- 센터 설명, 지향점, 확장 목표 중 외부 공개 가능한 사실.
- 복지·제공 혜택, 급여·근무·휴무·복장·고객관리 규정.
- 신입·경력 모집 조건, 우대사항, 채용 절차.
- 개인정보 수집·이용 동의문, 보관기간, 개인정보 문의처.

자료가 없는 구간에 가짜 수치, 경력, 인용문, 지점 계획을 만들어 넣지 않는다. 공개 승인되지 않은 정보는 UI에서 해당 항목 자체를 숨긴다.

## 13. 테스트와 검수

- 공개 홈, 지원서, 관리자 화면의 렌더링과 경로 테스트.
- 신입·경력 조건부 필드 테스트.
- 정상 제출, 필수값 누락, 글자 수, 허용되지 않은 파일, 10MB 초과, 네트워크 실패 테스트.
- 제출 후 DB·파일 일치 여부와 실패 시 파일 정리 테스트.
- 익명 사용자의 목록·상세·파일 읽기 차단 테스트.
- 관리자 로그인, 역할, 목록·상세, 상태 변경, 평가·메모, 임시 다운로드 주소 테스트.
- 320/360/390/430px와 데스크톱에서 시각 검사.
- 키보드, 포커스, 오류 요약, 색상 대비, reduced-motion 검사.
- 실제 데이터 대신 테스트 전용 가상 지원자만 사용.
- 프로덕션 빌드와 Cloudflare 미리보기 배포 확인.

## 14. 단계적 출시

1. 브랜드·콘텐츠 자료 확정.
2. 공개 사이트와 반응형 디자인 구현.
3. 단계별 지원서와 제출 API 구현.
4. DB 정책, 관리자 인증, 목록·상세·평가 구현.
5. 보안·접근성·모바일·전체 흐름 검수.
6. 개인정보 동의문과 보관 정책 최종 승인 후 공개.

무료 한도에서 시작하되 지원서 파일이 1GB에 가까워지거나 상시 운영 안정성, 자동 백업, 장기 감사 로그가 필요해지는 시점에는 유료 전환 결정을 먼저 받는다.
